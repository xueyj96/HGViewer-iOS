# 账号状态与弹层生命周期

2026-11-13。本轮从 1.2.5 的上一轮本地重构继续，处理实际复现的账号乱序覆盖和弹层收尾分叉；不改变下载实现、账号文件格式或页面尺寸。

## 责任边界

`useAccountSession` 是前端账号状态和认证操作的唯一所有者。Store 保留稳定 facade；登录表单只持有输入、错误和展示生命周期。表单关闭不撤销已经提交的有效认证，但旧表单的完成结果不能关闭新表单、清空新密码或改变新表单的 busy 状态。

每次账号意图推进 revision。开机读回、登录、注册、退出和线路重置，只允许当前操作提交账号结果。开机的全局配置与账号结果分开接收，避免登录开始后丢掉安全配置。未知读回保留最后已知状态，并提示未确认；只有明确的 guest 或合法账号才能作为新状态。

退出有两个不同生命周期：Promise 表示这次请求资源是否仍在使用，`readbackRequired` 表示退出后是否还需要核对账号。请求结束不能自动消费后者。连续替代认证失败时，仍由当前 revision 读回原生账号；有效认证、线路重置或明确读回才能结束这项业务责任。

## 原生会话

`SessionStore` 用同一把锁保护内存状态、revision 和持久化顺序。`SessionOperation` 是不跨 await 持锁的认证 lease；失败或丢弃只退役自己尚有效的操作，不能清掉已接受账号。账号响应必须包含非空 token 和正的安全整数 user id，才能提交。

`SessionSnapshot` 原子捕获 token、user 和 revision。`api_me` 必须携带同一快照完成请求和提交，避免旧 token 的响应与新账号混配。退出先撤销目标 origin 的本地凭据，再进行远端请求；远端完成后不再写账号。已接受账号和进行中的其他 origin 认证分别处理，不能互相误清。

磁盘继续使用原有 `session.json` 结构；写临时文件后原子替换，在锁内保持与内存相同的先后顺序。持久化失败仍按既有 best effort 语义处理，只记录不含凭据的错误类型并清理本次临时文件。当前实现不保证磁盘写入失败后的跨进程持久性，也不把内存成功宣称为落盘成功。

## 视觉收尾

Sheet 与 Modal 共用 `useMotionPresence`，只等待根元素本轮动画完成或取消后释放视觉层。重新打开会撤销旧收尾；子元素无限动画不会拖住退出。拖动关闭保留原有即时退出路径，焦点和 inert 仍由各容器管理。

`finishMotion` 的完成表示视觉资源可以清理，不表示业务成功。减少动态效果时同时收紧 CSS animation 与 transition；普通模式的布局、配色和动画时长保持原有定义。

## 回归入口与边界

先启动 `pnpm dev`，再运行 `pnpm test:browser`。测试环境需提供 Playwright；已有安装可通过 `HG_PLAYWRIGHT_MODULE` 指向，Chrome 可通过 `HG_CHROME_EXECUTABLE` 指定。可选 `HG_TEST_REPORT_DIR` 保存逐组 JSON。末尾可附 fixture 名称只运行选定组。测试 runner 不安装依赖、不连接真实账号服务。

账号组使用真实 React Store／表单和模拟 native API，覆盖乱序、线路变化、退出失败读回、未知读回、连续替代、卸载和重开；视觉组在普通／减少动态效果两种模式覆盖关闭、取消、重开、焦点和可信触摸拖动。Rust 单元测试验证 lease、origin、读回、并发持久化及旧磁盘格式。

浏览器模拟 IPC、host Rust 单测及 iOS target 编译各自证明对应边界；它们不替代 WebKit、真实账号服务、手机旋转或后台下载验收。本轮不变更版本、不安装手机、不发布。详细运行证据保存在本地 `build/verification/account-20261113/`，该目录不属于公开源码。
