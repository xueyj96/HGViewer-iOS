# 三 App 共通契约补充：身份、结果与生产来源

2026-11-12。本文补充既有[结构契约 v1](cross-app-architecture.md)，服务于 HGViewer、ExHViewer 与 CivitViewer 的后续收敛。当前是跨会话审阅中的第二轮方案；HG 实施与验证单独记录，不能据此宣称另外两个 App 已迁移。各工程保留自己的源码写入者。

## 共用范围

三 App 共用职责、行为和验收语义。HG 继续 React/Tauri、Rust 与 Objective-C；ExH 和 Civit 继续 SwiftUI/UIKit。现阶段不建立跨语言运行库，不增加全局 Manager，不为抽象统一业务策略。小型纯函数和无副作用组件保持简单；只有两个真实消费者存在相同规则和变化原因，才考虑公共包。

| 可交换的内容 | 当前形式 | 不应统一的差异 |
| --- | --- | --- |
| 控件可见面、点击区、间距、文字、色调、安全区 | 语义角色及带生产来源的快照 | CSS px 与 Swift pt；平台字体、各 App 已确认的尺寸和例外 |
| 导航、业务与视觉结果 | 下述有身份的结果契约 | ExH 点击返回只退出、边缘执行有效条件；Civit 自己的草稿与云端确认；HG 播放及来源返回 |
| 媒体和下载生命周期 | 会话身份、资源释放、取消和迟到结果用例 | Reader 页状态、短剧切集、混合图文媒体、站点权限与文件格式 |
| 回归场景 | 同一状态序列，各平台分别执行 | 浏览器模拟 IPC、模拟器与真机证据不能互相替代 |

## 三类结果不能共用一个 completion

下面是行为模型，不要求三个工程复制相同类型或枚举。

| 结果 | 最小上下文 | 表达什么 | 不能据此推导 |
| --- | --- | --- | --- |
| BusinessOutcome | operationID、业务对象、dataContext | 本地应用成功、远端确认、拒绝、取消、失败或未确认 | 页面已经关闭、动画已经结束 |
| NavigationOutcome | routeInstance、navigationIntent | 目标已接受、实际到达、返回取消或被替换 | 收藏已同步、下载已完成 |
| VisualOutcome | visualSession、from/to、目标几何 | 动画完成、交互取消或环境中断 | 导航或业务成功，以及是否应重试写入 |

三类结果各自终止。动画中断不得改写此前已确认的业务或导航结果，也不得自行重试网络操作。无动画、减少动态效果和系统中断仍必须完成对应的资源清理。

HG 的 `finishMotion` 等待当前动画无论成功或取消后收尾，适合移除视觉快照、退出层和释放本次视觉资源。它不是“业务成功”的凭据。若调用者需要区分正常完成与中断，应在该动作边界表达结果，不能改变所有 cleanup 的语义。11 月 12 日曾保留 Sheet 的计时器与实际动画双路径；11 月 13 日在半屏／整页、快速关闭重开、取消动画、焦点回交和减少动态效果验证后，已统一到视觉专用 `useMotionPresence`，详见[本轮责任边界](account-session.md)。

## 身份和副作用

异步操作先确定所属范围，再决定失效方式。scope 至少包含其依赖的线路／账号 revision，按业务加入 routeInstance、内容会话和 attempt。它们不能合成一个通用 key：同内容重试是新 attempt，但不是新观看记录；视觉反向是新视觉过程，但不是第二次收藏提交。

- React 状态 updater 必须纯粹。事件先明确目标值，例如 `setLikedLocal(id, true)`；提示和请求使用同一目标，不从 updater 的执行时机取得返回值。
- 页面关闭可以结束自身订阅与轮询；服务拥有的下载和可续传分片不因此取消或删除。
- 共享读取只有一个实际请求 owner。操作成功后的刷新不能复用操作之前已经发出的读取；旧结果失效后应等待旧读取结束，再请求新状态，避免并发扫描和旧快照回写。
- 每个资源由取得它的 owner 幂等释放。旧路由、旧 attempt 或旧动画只能清理自己的资源，不得影响后来者。
- 预览只显示外观。可画目标预览不等于目标数据就绪，不启动真实请求、菜单、播放或导航副作用。

## 设计 token 的交换与生成

生产来源仍为 HG 的 CSS，以及两个原生 App 各自的 Swift 常量。候选 JSON、人工规范和报告均不成为第二份可手改的运行时来源。

HG 的 `node scripts/design-token-snapshot.mjs` 从生产 CSS 只读生成快照。报告包含 schemaVersion、application、来源文件 SHA-256、角色与变量映射、原始表达式和解析范围。字面长度可报告数值；`var()`、`calc()`、安全区和主题／媒体条件未实际计算时保留表达式及未解析标记。来源哈希包括输入样式文件，但不冒充已解析完整级联或所有 JS 动效。

各 App 可以选择不同值；先核对“点击区”和“可见面”等角色含义是否相同。未来若确有两个生成器消费者，再确定公共 schema、版本兼容和单向生成流程，先删除人工双写入口，再接入构建检查。暂不抽出共享 UI 或导航容器。

## 第二轮 HG 实施与停止条件

本轮先处理真实发现的横切责任：本地目标动作、持久化规范化、Toast 展示订阅、缓存快照读取和独立请求并发；保留已验证的播放器来源／进度／手势分责及原生下载实现。具体修改、来源指纹与回归结果见[整体优化记录](architecture-review-20261112.md)。

一个责任完成迁移，需要旧路径删除、实际消费者接入、失败／取消／失效结果通过验证。抽出文件数量和代码行数不作为验收。没有性能测量的地方只记录结构成本，不声称帧率、耗电或速度已改善。完成相应检查后停止本轮，不以“最佳实践”要求无边界改写。
